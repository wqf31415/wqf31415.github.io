### 为什么要用 LangGraph

LangGraph 是图结构，在此之前出现的链式结构的 LangChain，LangChain 适合简单的线性任务场景，底层设计局限导致无法满足复杂的Agent场景，LangGraph的设计适合解决复杂决策问题。

#### LangChain 的优缺点

优点：

- chain是线性的流水线执行，逻辑简单直观，易于理解，把prompt、模型、解析器串联起来就可以了
- 生态丰富，官方和社区提供了大量组合工具、模型、解析器，不需要从零开始造轮子
- 非常适合快速验证想法，语法简单、封装度高，五分钟就能跑通Demo，从灵感到原型的时间短，试错成本低

局限性：

- 无法回溯，单向执行，错了不能回头，支持一直走完。一步错误的信息会持续影响后续所有推理，无法自我修正
- 没有原生的状态管理，仅传简单数据，复杂上下文需要手动管理，人为管理易造成中间变量丢失
- 无法分支，只能线性顺序执行，无法根据中间结果动态选路，灵活性严重不足
- 没有记忆，对话历史需要手动拼接到prompt中，状态一致性难以保证，容易出现前后对不上的情况

#### LangGraph 相较于 LangChain 的优点

- 执行流：Graph 是拓扑网络结构，支持循环、分支、并行。chain是单向线性，固定顺序执行。
- 数据传递：支持全局State共享，完整上下文传递。chain使用单值链式传递，信息承载有限。
- 分支能力：内置条件边，从代码层面保证了执行逻辑的确定性。chain中只能靠prompt诱导，具有很大不确定性。
- 容错能力：graph支持重试、兜底、断点续跑。chain没有容错能力，一步错全链崩，没有重试机制。

#### LangGraph 的核心价值

- 确定性编排：把决策流从黑盒prompt变成了白盒的代码，决策流可视化、可测试、可追踪，逻辑是可预测、可调试、可监控的。
- 状态驱动设计：提供了统一 State 抽象，多轮对话/工具调用/记忆管理的标准载体，降低复杂交互开发成本。
- 面向生产的工程化底座：实现了Checkpoint断点续跑、Human-in-the-loop 人工介入、Streaming 流式输出，直接用于生产级环境。

### LangGraph图结构的三大核心要素

#### 节点（Node）

节点是最小执行单元，每个节点负责一件具体的事情，比如完成LLM调用、工具调用、函数调用、数据处理等操作。

#### 边（Edge）

边是节点和节点之间的流转逻辑，可以是线性流转，也可以是条件决策流转。

#### 状态（State）

状态是整个图结构最核心的东西，是全局共享记忆中枢，所有节点都可以读写，实现了节点间的数据同步与共享。所有的上下文、中间结果、历史对话都存在状态中。
